# Изменения в этом форке

Форк [amorev/cmp-30hx-agent](https://github.com/amorev/cmp-30hx-agent) с правками по итогам
код-ревью. Исходный код и документация сохранены без изменений, кроме перечисленного ниже.

## Критичные исправления

### 1. История tool-раундов хранит сырой ответ с разметкой вызова
`voice/app.py` (Turn.run). Раньше в историю попадал отфильтрованный `done["text"]`,
из которого вырезан `<tool_call>` — вопреки разделу 7 README («в историю пишется сырой
текст генерации `done.raw`»). Последствия были двойные: модель не видела, что уже
вызывала функцию (повторные вызовы, «не знаю»), а следующий промпт расходился с KV,
поэтому кэш частично пересчитывался.

Теперь:
- в историю идёт `done["raw"] or done["text"]`;
- порядок истории хода: `user` → `assistant(raw с вызовом)` → `tool(результат)` →
  `assistant(финальный ответ)`, а не «ассистент, инструмент, потом вопрос»;
- `is_continue=True` для продолжения после инструмента (без дублирования реплики).

### 2. Восстановление после неудачного decode в демоне
`daemon/bonsai_daemon.cpp`. `decode_range()` декодирует промпт кусками; при ошибке
на середине KV уже продвинут, а `kv_tokens` — нет. Следующий `common_prefix()` считался
по устаревшему вектору и декодировал токены поверх занятых позиций (мусор в KV,
влияющий на последующие ответы).

Добавлено `Daemon::recover_after_decode_failure()`: снапшот базы + сброс `kv_tokens`,
ответ клиенту `{"error":"decode_failed","recovered":true}`. Вызывается из `prefill`,
из обеих веток `generate` и при ошибке `decode_one`.

Дополнительно: `rollback(n < base_tokens)` больше не оставляет KV на базе с последующим
декодом с чужой позиции — сразу восстанавливает базу.

### 3. `stat`/`/health` не ждут окончания генерации
- `voice/llm_client.py`: `stat()` уходит отдельным коротким соединением (`_oneshot`),
  не вставая в общий `asyncio.Lock`, который занят на всё время стрима.
- `voice/app.py`: `/health` больше не ходит в демон и не вызывает `ensure_tools`
  (он мог сделать `set_tools` ≈4 с и стереть KV). Отдаётся последний снимок из
  фонового `_stat_refresher` (интервал 2 с) + `llm_stat_age_s`.
- `ensure_tools` вызывается только из рефрешера.

> Остаточное ограничение: сам демон однопоточный, поэтому `stat` во время генерации
> всё равно ждёт её окончания. Смягчено кэшем на стороне voice-сервиса; полноценное
> решение — вынести генерацию в отдельный поток демона.

## Умный конец реплики, перебивание, wake word (12.11.2026)

- **`voice/turn.py`** — адаптивная пауза конца реплики (вместо фиксированных 1.2–2.4 с
  sherpa): законченная фраза («?», «.») — 350 мс; вопрос без знака — 500; обычная — 600;
  оборвано на союзе/предлоге/вопросе («и», «в», «сколько») — 1200; одно слово — 800;
  потолок 2500. Фразу закрываем не позже `hold+400` мс тишины, иначе CTC «дописывает»
  текст на тишине и пауза расползается. Поздние партиалы больше не сбрасывают таймер.
- **`voice/asr.py`** — VAD по RMS с hangover 350 мс (события `speech_start/speech_end`),
  режим `ASR_ENDPOINT=smart|sherpa`, потокобезопасный `request_finish()` (Event +
  блокировка), recognizer кэшируется на процесс и собирается в воркере: первый клиент
  больше не блокирует event loop на ~2 с.
- **Перебивание** — в браузере: анализ RMS микрофона, пока играет ответ (порог 0.022,
  ~180 мс речи → `barge_in`), локальная остановка воспроизведения; на сервере
  `Session.interrupt()`: гасит TTS-очередь, отменяет текущий ход, сбрасывает ASR.
  Проверено: событие `interrupted` приходит сразу.
- **Wake word** — `WAKEWORD_MODE=asr` (по умолчанию): постоянно слушаем ASR и ждём
  ключевую фразу из `WAKEWORD_PHRASES` («джарвис», «ассистент») — работает для русского
  без обучения модели; поиск нечёткий (`с/з`, `д/т`, `и/ы` — ASR путает «джарвис» →
  «джарвиз»). Альтернатива `WAKEWORD_MODE=oww` — openWakeWord 0.4 (английские модели,
  пути берутся из пакета). Фразы без ключевого слова игнорируются, слово вырезается из
  вопроса. Проверено: без слова — тишина, с «Джарвис, …» — событие `wake` + ответ.
- **UI** — чекбокс «wake word», индикация события `wake`, лог перебивания.

Замеры на целевой машине (`tests/test_turn_and_barge.py`):

| Фраза | Пауза VAD→final | Всего после речи |
|---|---|---|
| «Сколько стоит биткоин сегодня.» | **989 мс** | 994 мс |
| «я хотел купить хлеб и» | **1683 мс** | 1993 мс |

## Действия: музыка, видео, сайты (12.11.2026)

- **Музыка со звуком на этом ПК**: `tools.play_music()` — `yt-dlp` находит первый
  результат YouTube (`ytsearch1`), `ffplay` играет аудиопоток через WSLg
  PulseAudio (`PULSE_SERVER=unix:/mnt/wslg/PulseServer` подставляется сам).
  `stop_music()` останавливает, `music_now_playing()` — что играет.
  `MUSIC_PLAYBACK=host|browser` переключает на открытие сервиса в браузере.
- **Видео и сайты**: `video_search()` открывает поиск YouTube, `music_search()` —
  музыкальный сервис (YouTube Music/Spotify/Яндекс/SoundCloud), `open_site()` —
  разрешённый домен. Действие возвращается маркером `__ACTION__` + JSON; сервер
  проверяет домен по `ACTION_DOMAINS` и шлёт клиенту событие `action`, а модели и
  истории отдаёт человекочитаемый текст без маркера.
- **Детерминированный роутер** `tools.route_action()`: короткие команды
  («включи музыку …», «выключи музыку», «найди видео про …», «открой сайт …»)
  выполняются **без генерации** — быстрее и не зависит от того, выберет ли 9B
  инструмент. Остальные запросы идут через модель.
- **UI**: под ответом появляется кнопка «▶ Открыть», событие дублируется в лог;
  автооткрытие вкладки может блокироваться браузером — кнопка остаётся.
- **Тесты**: `tests/test_actions.py` (ссылки, allowlist, роутер),
  `tests/test_play.py` (ffplay жив через 6 с — звук реально идёт),
  `tests/test_action_ws.py` (живой сервис).

Проверено на целевой машине:

| Команда | Инструмент | Результат |
|---|---|---|
| «включи музыку Rammstein Sonne» | `play_music` | играет, ffplay жив, «Включаю «Rammstein Sonne»…» |
| «выключи музыку» | `stop_music` | «Остановил музыку…» |
| «найди видео про сборку ПК» | `video_search` | action → `youtube.com/results?search_query=…` |
| «открой сайт youtube.com» | `open_site` | action → `https://youtube.com` |

Ограничения: управление только «играть/стоп» (без паузы и переключения треков);
часть видео YouTube может требовать PO-token (тогда yt-dlp вернёт ошибку — сервис
скажет об этом голосом); локальная медиатека не подключена.

## Docker-упаковка (12.11.2026)

- `docker/Dockerfile` — `nvidia/cuda:12.4.1-runtime-ubuntu24.04` + Python 3.12 +
  зависимости + отдельное окружение `.venv-silero` (torch CPU) + ffmpeg/espeak.
- `docker/entrypoint.sh` — поднимает silero → демон → voice, healthcheck на `/health`.
- `docker/docker-compose.yml` — один сервис, GPU-резервация, порт `127.0.0.1:8110`,
  тома с хоста: модели LLM/ASR/TTS, собранный `llama-prism/build`, бинарь демона, `.env`.
- `docker/.env.example`, `docker/README.md` — пути хоста и порядок запуска.
- `.dockerignore` — контекст сборки ~1 МБ вместо 5 ГБ (модели/venv/бинарники не входят).
- Проверено: `docker compose config` валиден, docker 29.1 + compose 2.40 в WSL.
  Образ `cmp-voice:local` собран (12.9 ГБ образ / 4.64 ГБ содержимое), контейнер
  запускается с GPU (nvidia-container-toolkit), `/health` = ok и изнутри, и с хоста,
  демон и Silero поднимаются. TCP-ход внутри контейнера не прогонялся (проверен на
  systemd-варианте тем же кодом); после теста systemd-сервисы возвращены, VRAM 2747 МиБ.

## Голос TTS и альтернативы поиску (12.11.2026)

- **Выбор голоса в интерфейсе**: `voice/app.py` — команда `tts_voice` (валидация по
  списку голосов движка, запрет во время хода), `tts_engine_set` теперь возвращает
  список голосов, `Session.tts_voice` передаётся в `backend.stream(text, voice)`.
  `voice/static/index.html` — `<select id="selVoice">` рядом с переключателем движков,
  голос запоминается в `localStorage` отдельно для каждого движка, блокируется на время хода.
- **Провайдеры веб-поиска** (`voice/tools.py`, `voice/config.py`): `SEARCH_PROVIDER`
  = `auto|ddg|tavily|brave|searxng|wormsoft`.
  `auto`: tavily (ключ) → brave (ключ) → searxng (URL) → wormsoft (токен) → **ddg**
  (бесплатно, без ключа, `html.duckduckgo.com`). `web_fetch` без wormsoft-токена
  читает страницу напрямую через urllib. В `/health` добавлен `tools_token.provider`.
  Ключи: `TAVILY_API_KEY`, `BRAVE_API_KEY`, `SEARXNG_URL`, таймаут `SEARCH_TIMEOUT`.
  Если выбранный провайдер падает — автоматический фолбэк на DDG.
