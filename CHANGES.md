# Изменения в этом форке

Форк [amorev/cmp-30hx-agent](https://github.com/amorev/cmp-30hx-agent) с правками по итогам
код-ревью. Исходный код и документация сохранены без изменений, кроме перечисленного ниже.

## Критичные исправления

### 1. История tool-раундов хранит сырой ответ с разметкой вызова
`voice/app.py` (Turn.run). Раньше в историю попадал отфильтрованный `done["text"]`,
из которого вырезан `<tool_call>` — вопреки разделу 7 README («в историю пишется сырой
текст генерации `done.raw`»). Последствия были двойные: модель не видела, что уже
вызывала функцию (повторные вызовы, «не знаю»), а следующий промпт расходился с KV,
поэтому кэш частично пересчитывался.

Теперь:
- в историю идёт `done["raw"] or done["text"]`;
- порядок истории хода: `user` → `assistant(raw с вызовом)` → `tool(результат)` →
  `assistant(финальный ответ)`, а не «ассистент, инструмент, потом вопрос»;
- `is_continue=True` для продолжения после инструмента (без дублирования реплики).

### 2. Восстановление после неудачного decode в демоне
`daemon/bonsai_daemon.cpp`. `decode_range()` декодирует промпт кусками; при ошибке
на середине KV уже продвинут, а `kv_tokens` — нет. Следующий `common_prefix()` считался
по устаревшему вектору и декодировал токены поверх занятых позиций (мусор в KV,
влияющий на последующие ответы).

Добавлено `Daemon::recover_after_decode_failure()`: снапшот базы + сброс `kv_tokens`,
ответ клиенту `{"error":"decode_failed","recovered":true}`. Вызывается из `prefill`,
из обеих веток `generate` и при ошибке `decode_one`.

Дополнительно: `rollback(n < base_tokens)` больше не оставляет KV на базе с последующим
декодом с чужой позиции — сразу восстанавливает базу.

### 3. `stat`/`/health` не ждут окончания генерации
- `voice/llm_client.py`: `stat()` уходит отдельным коротким соединением (`_oneshot`),
  не вставая в общий `asyncio.Lock`, который занят на всё время стрима.
- `voice/app.py`: `/health` больше не ходит в демон и не вызывает `ensure_tools`
  (он мог сделать `set_tools` ≈4 с и стереть KV). Отдаётся последний снимок из
  фонового `_stat_refresher` (интервал 2 с) + `llm_stat_age_s`.
- `ensure_tools` вызывается только из рефрешера.

> Остаточное ограничение: сам демон однопоточный, поэтому `stat` во время генерации
> всё равно ждёт её окончания. Смягчено кэшем на стороне voice-сервиса; полноценное
> решение — вынести генерацию в отдельный поток демона.

## Важные исправления

| Файл | Что изменено |
|---|---|
| `daemon/bonsai_daemon.cpp` | немедленный EOG теперь отдаётся как `finish:"eog"` (а не `length`), клиент может повторить ход осознанно |
| `daemon/bonsai_daemon.cpp` | `send_line` при `EAGAIN` ждёт `POLLOUT` вместо молчаливого обрыва строки (клиент получал битый JSON) |
| `daemon/bonsai_daemon.cpp` | `part4` системного промпта («вызови функцию повторно, если данных нет») наконец включён — он был объявлен, но не использован |
| `daemon/bonsai_daemon.cpp` | убран мёртвый код (`(void) m` в `set_tools`, пустой блок в `decode_one`), добавлен `<cerrno>` |
| `voice/app.py` | двойной немедленный EOG даёт явную ошибку и `turn_end(reason="empty_answer")`, а не пустой ответ |
| `voice/app.py` | бюджет хода `VOICE_TURN_TIMEOUT` (по умолчанию 30 с): зависший MCP/демон/WS не держит сеанс в `busy` |
| `voice/app.py` | переключение TTS — свойство сеанса, а не глобальное (`tts_registry.active` больше не меняется чужим клиентом) |
| `voice/asr.py` | ограниченная очередь PCM (≈20 с) с выбросом старых кадров и счётчиком потерь вместо неограниченного роста памяти |
| `voice/tts.py` | битый chunked-ответ Silero — явная `TTSError` (502), раньше поток молча обрывался и клиент получал усечённое аудио |
| `voice/config.py` | новый параметр `VOICE_TURN_TIMEOUT` |

## Инфраструктура

- `requirements.txt` — зависимости voice-сервиса и отдельного CPU-окружения Silero.
- `tests/test_tool_history.py` — регрессии на пункты 1 и «двойной EOG» (без GPU, сети
  и демона: LLM и инструменты подменяются; при отсутствии fastapi/uvicorn/numpy
  тест ставит минимальные заглушки, поэтому запускается и локально, и в CI).
- `.github/workflows/ci.yml` — `compileall` для `voice/`, `silero/`, `tests/` +
  запуск регрессий на Python 3.12. Сборка C++ демона в CI намеренно не делается:
  нужен форк llama.cpp с `PQ2_0` и CUDA.
- `.env.example` — добавлен `VOICE_TURN_TIMEOUT`.

## Что НЕ проверено в этом форке

- C++ демон **не собирался** здесь: для сборки нужен форк `PrismML-Eng/llama.cpp`
  с типом `PQ2_0` (см. `scripts/build_daemon.sh`). Правки в `bonsai_daemon.cpp`
  синтаксически выверены вручную, но прогон на железе — за вами.
- Замеры из `REPORT.md` относятся к исходной версии; после правок цифры prefill/кэша
  должны улучшиться (меньше ложных пересчётов), но перезамер нужен.
- `LICENSE` не добавлен: лицензия исходного репозитория не указана, а менять
  юридический статус чужого кода без решения автора нельзя.
